# Stand2Knee 末帧独立手臂控制（2026-10-28）

默认跪下／起立策略现已分别更新为 `model_stand2knee_1028.onnx`、`model_knee2stand_1028.onnx`，
配套训练配置分别为 `agent(13).yaml`／`env(13).yaml`、`agent(14).yaml`／`env(14).yaml`。
新模型接口及验证见 [1028模型更新](stand2knee_1028_verification.md)。下文稳定性数据为1027模型的历史验证。

`stand2knee_mimic_state` 在首次执行参考帧383时接管双臂，即进入状态约7.66秒后。
跪下过程仍使用原始29维策略动作；到末帧后，腰腿继续由同一ONNX策略根据实际机身／腰腿反馈控制。

## 末帧行为

按已确认的默认手臂角度处理：实际手臂位置观测固定为ONNX元数据中的 `default_joint_pos`，
因此151维观测中手臂的相对位置分量为0；手臂速度和上一策略动作也为0。
左右臂对应的14个策略输出置零，并用独立手臂控制器的位置目标覆盖，实际手臂不受ONNX手臂动作驱动。

模型导出的末帧参考命令（观测最前面的参考位置／参考速度）保留。
参考命令定义腰腿策略执行的任务，不属于实际关节反馈；试验中把它也改成默认手臂姿态会导致腿部输出突变，13.488秒触发高度保护。
最终实现保留原始参考命令。

独立控制复用 [RLArmMotionPlanner](../run_policy/cr1pro/include/rl_arm_motion_planner.hpp)，Stand2Knee单独配置前两组预设：

- 接管时从当时的实际左右手臂角度开始保持。
- 按 `1` 双臂向前伸直，按 `2` 双臂水平向左右展开；从当前规划目标用2.4秒五次插值到达并保持。`3..6` 保留既有预设，`6` 为home姿态。
- 使用状态机已有的 `ControllerData::udp_node` 接收14轴UDP目标，沿用手臂限位和限速，并反馈真实关节状态。
- 独立手臂kp为 `[300,100,100,100,40,40,40]`，kd为 `[15,3,3,3,2,2,2]`，左右相同，来源为RL Stand。
- 实际反馈仍用于PD、独立手臂规划及关节保护，冻结仅发生在模型观测中。
- 退出／重入清除接管和插值状态；`Y` 进入原Knee2Stand，起立后 `C` 返回AMP Walking，`R` 仍可急停。

实现位于 [状态入口](../state_machine/humanoid_pro/stand2knee_mimic_state.hpp) 和
[knee_mimic_policy_runner.cpp](../run_policy/cr1pro/src/knee_mimic_policy_runner.cpp)。
提供的ONNX、YAML和RL Stand源代码没有修改。

## 使用

进入Stand2Knee约7.66秒后启动独立手臂控制，之后按 `1..6` 操作双臂；按 `Y` 起立，等待至少7秒后按 `C`。

当前 `1`／`2` 目标如下（单位：度；SDK顺序为肩pitch、肩roll、肩yaw、肘pitch、腕yaw、腕pitch、腕roll）。仅Stand2Knee的末帧独立手臂使用这些目标，普通RL Stand和MoE保留原预设。

| 按键 | 左臂目标 | 右臂目标 |
|---|---|---|
| `1` 前伸 | `[-90,0,0,90,0,0,0]` | `[-90,0,0,90,0,0,0]` |
| `2` 侧展 | `[0,90,0,90,0,0,0]` | `[0,-90,0,90,0,0,0]` |

B2模型中肘pitch为90度时前臂与上臂伸直，零度时为弯肘。动作进行中再次按 `1`／`2` 会从当前规划目标重新平滑切换；末帧前的按键请求会在末帧接管时执行。

1028模型长期摆臂后切入Knee2Stand有既知的高度保护触发记录，见 [1028模型验证](stand2knee_1028_verification.md)。本次前伸／侧展验证仍复现了该问题，稳定性结论仅覆盖Stand2Knee内的手臂动作与跪姿保持。

## 历史稳定性结果（1027模型及原预设）

1027模型的55秒历史验证通过，状态顺序为Idle → AmpZeroPos → AmpWalking → Stand2Knee → Knee2Stand → AmpWalking。
末帧手臂控制连续保持约30秒，整个动作阶段无底座支撑。
`fault_latched=false`、`fall_event=null`、`failures=[]`；最终base高度约0.888 m。
末帧接管后最低base高度约0.468 m，最大绝对roll/pitch约0.051 rad。
左右肘实际活动范围分别约1.367 rad、1.370 rad，确认手臂实际运动而非只改变目标。
原有0.45 m／1 rad保护阈值、PD物理执行和关节保护保持启用。

C++回归9/9通过，包括：

- 全部轨迹帧和100个末帧保持的独立ONNX数值对照；扰动实际手臂反馈后验证冻结观测及腰腿输出。
- 与RL Stand共900周期的预设、插值、禁用／恢复和PD参数对照。
- 本地UDP回环验证末帧前不接管、14轴目标接收、限速及真实手臂状态反馈。
- 重入、虚拟neck隔离、错误模型及NaN故障回退。

MuJoCo专项3/3通过，包含原完整切换流程、重入／阻尼流程，以及新增48秒自由底座六组手臂预设和起立返回行走。
新增物理回归末帧阶段最低base高度0.4677 m、最大绝对roll/pitch为0.0503 rad；检查了两个肘的实际活动范围、保护拒绝计数和虚拟neck零输出。

```bash
ctest --test-dir build/pro-tests --output-on-failure
```

稳定性结论限于项目现有B2 MuJoCo模型和已测预设；UDP验证覆盖协议、接管和限速。

## 当前前伸／侧展的起立衔接检查

本次使用双1028策略，两轮 `1 → 2` 的目标角度、实际关节角和手腕方向检查均通过。
回到home预设 `6` 后再切入Knee2Stand，等待3秒和6秒的两组试验分别在37.181秒和37.250秒触发0.45 m高度保护。
该结果与 [既有1028验证](stand2knee_1028_verification.md) 记录的长期摆臂后起立问题一致；本次没有修改Knee2Stand策略或放宽保护阈值。
